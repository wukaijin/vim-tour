## 1. 产品定位

- 单页应用（SPA）：通过实操闯关游戏学习 vim。
- 目标人群与终点线：**零基础 → 日常编辑熟练**。终点定义：能脱离鼠标用 vim 完成真实编辑工作。
- 范围内：移动、operator+motion、text object、visual 模式、查找替换、多行编辑、基础寄存器。
- 范围外（首版）：宏、quickfix、插件配置、vimrc 教学。可作为后续彩蛋章节。

## 2. 核心游戏机制：次数 + 效率双轨

### 2.1 通关判定（次数轨，肌肉记忆）
- 每个任务需**连续成功 N 次**才算掌握，N 随章节递增（默认值：第 1 章 N=1，第 2 章起 N=2，第 4 章起 N=3）。
- 中途失败清零连续计数，重做该任务。

### 2.2 星级（效率轨，驱动重复）
- 3 星：击键数 ≤ par，且未看提示、未用撤销。
- 2 星：击键数 ≤ 1.5 × par。
- 1 星：完成即得。
- par 由每题内置的最优解按键序列计算（构建时跑在引擎上验证正确性）。
- **变体口径（v2）**：**par 取当前变体的 `parKeys`，`bestStars` 取历史最优**——长短变体各自公平，且因变体按日期种子轮换（见 2.4）而无法重投短变体刷分。

### 2.3 累积复习（毕业考）（v2 改名，原「间隔重复（复合训练）」）
- 每章最后一关为**毕业考**：综合题需组合本章及此前所有章节的命令才能高效解开。
- 考题使用**未在任何关卡变体中出现过的 fresh 文本**（迁移测试的本分）。
- 通过后对**所有被考到的既往关卡批量执行一次清关更新**（刷新 `lastPlayedAt`、`srsStage +1`）——复用已有更新函数循环，零新机制。
- 第 7 章整章为真实场景实战（重构函数、批量改名、改配置文件等）。

### 2.4 锈蚀与复习（v2 新增：跨天维持层）

**核心主张：引入间隔重复的原理，不引入 SRS 的机器。** 理由：①SM-2/FSRS 为二值判定（想起/想不起）的卡片设计，本作最小单元是「带效率评分的动作执行」，判定天然分级；②FSRS/半衰期回归需复习历史流拟合，本作只有 localStorage、无埋点，10–14 关体量拟合任何参数都是自欺；③现有双轨已是合格的**习得期**设计（次数轨=会话内重复提取，效率轨=精炼式刻意练习），真正缺的只是**跨天维持期**——习得期机制一律不动，只加一层薄维持机制。

**A. 锈蚀模型**
- `due = now - lastPlayedAt > LADDER[srsStage]`，`LADDER = [1, 3, 7, 14, 30]` **天**（以天为单位：动作巩固依赖睡眠，会话内重复复习无巩固收益；取扩展间隔而非等距，Cepeda et al. 2006）。
- 转移规则：首次达标 → `srsStage=0`；此后每次清关 → `s+1`（封顶 4）；失败 → `s-1`（地板 0）；两者都刷新 `lastPlayedAt`；**同日多次清关只扩展一次**（按 `lastPlayedAt` 日历日判断，零新字段），防当天连刷顶满间隔。
- 算法件唯一：`game/retentionOf(record, now)` 纯函数。**硬条款：`now` 从参数注入，函数体内禁止 `Date.now()`**，`game/` 内所有时间读取走注入的 clock——否则 30 天档永远测不到，只能上线等一个月。
- **硬条款：锈蚀是邀请不是惩罚。** 生疏只做两件事——章节地图节点进 `due-review` 态、进热身队列。**永不回收星星、永不回退进度、永不锁下一章**；且只对**已通关章节**生效，推进中的章节内不出现生疏状态。

**B. 文本变体（习得期机制，非复习期机制）**
- 连续成功 N 次与所有热身复现均**轮换变体**。理由：固定文本下第 2 次成功判定执行的是已记住的方案——测的是**再认不是提取**；星级同被污染（rep 2 拿 3 星测的是复述不是寻路）。变化练习的情境干扰效应（contextual interference）在保留与迁移测试上优于重复同一条件。
- 数据形态：`texts: [{ start, target, cursor, parKeys }] × 2`（原文本 + 1 变体，MVP 不要第 3 个）。
- 作者规约（已升级为 CI 门禁，见 §9）：变体保持**相同行数、逐行前导空白完全相同、光标落在同一行**（空间骨架固定、词汇内容变——布局跳变的视觉噪音会吃掉情境干扰收益）；实现为**逐词一对一替换**（词数不变 ⇒ `parKeys` 完全复用，作者边际成本 ≈ 5–10 分钟/关）。
- **轮换按日期做种子**：会话内稳定、隔天必换，兼作防刷分（变体若随重试轮换，玩家可重投短变体刷 3 星）。
- **MVP 配置：ch2 全量配变体（不可砍——砍了等于让 M3 验证一个失真的判定器，难度与星级读数系统性偏乐观）；ch1 可延后为已知妥协**（N=1 无重复暴露；后果是 ch1 热身清关率读数偏高，试玩统计时 ch1/ch2 分层读）。

**C. 每日热身：≤90 秒的仪式**
- 进入章节地图时若存在 due 关卡 → 顶部全宽窄条热身卡：「3 个键帽生疏了 / 90 秒 · 可跳过」（纯 CSS + `<Keycap>`，零插画；Esc 立即跳过，当日收起，不占焦点陷阱）。
- 抽取规则（纯函数可单测）：due 优先 → `bestStars` 最低 → `lastPlayedAt` 最旧（弱势优先，全部来自现有字段）。
- 最多 3 题、目标 ≤90 秒、当日只出现一次、跳过零代价。热身清掉 = 正常清关（走 A 的扩展规则；看提示封顶 1 星照旧）。
- **硬条款：热身永远不是门禁**，毕业考与下一章解锁都不看它。它必须比倒杯咖啡还短，否则从「维持回路」退化成「每日任务」。

**D.（P2 彩蛋）组块可视化**
- 3 星结算屏把 `parKeys` 渲染成 `<Keycap>` 连排「你的连招」。**仅 3 星显示**（2 星/1 星显示等于把抄答案奖励化）；连续同键合并为 count 形态 `[3×][w]`；组块间 6px 间隙 + 小号「·」分隔，**不加连线箭头**（会把组块误导成流程图）。零新依赖，约半天，随时可插。

**E. 明确拒绝清单（「看起来游戏化但损害学习」专项）**
- 全量 SRS 调度器（SM-2/FSRS）。
- **Duolingo 式每日连击/登录 streak**：惩罚式断签机制，与「桌面工具、无账号、无同步」定位相斥；且 `streak` 一词已被 §2.1「关内连续成功」占用。
- 任何形式的衰减惩罚（摘星、锁关、清进度）。
- 提醒/推送（无后端本就做不了，写进不做清掉悬念）。
- 个性化动态 par（par 保持静态，可比性与作者 sanity 优先）。

### 2.5 按键白名单
- 第 1–4 章：每关白名单仅含已教按键，未教按键给轻提示「还没教到」。
- 第 5 章起：完全放开，等同真实 vim 自由度。

## 3. 任务形态：起始 → 目标 diff 制

- 屏幕呈现：起始文本（可编辑缓冲区）+ 目标文本（diff 对照）+ 任务描述。
- **成功判定 = 缓冲区内容与目标一致**，不比对按键序列——等价解法（`dw`/`de`、`cw`/`ce`）天然被接受。
- 光标位置默认不参与判定（特定关卡可选要求）。
- 不做「指令照做制」引导关，不做 golf 谜题关卡。

## 5. vim 引擎：自研轻量状态机

- TypeScript 实现，**纯逻辑、零 Vue 依赖**，可独立测试。
- 覆盖教学子集：normal / insert / visual（char/line/block）/ command-line（`:s` 简化实现）/ pending-operator / pending-count / pending-register 状态。
- 缓冲区 = 行数组；支持 undo/redo 栈、基础寄存器（unnamed、`"a-z`、`"0`）、计数前缀、`.` 重复。
- 按键白名单作为引擎外围的拦截中间件，不侵入核心状态机。
- 每次按键产出 state patch，UI 响应式渲染。
- **golden tests**：每个支持的命令一条「输入序列 → 期望缓冲区快照」测试；关卡 par 脚本在构建/测试时跑真引擎验证。

## 6. 教学与反馈

- **关前教学卡**：新命令 + 示例，可跳过。
- **按键回显栏**：实时显示 pending 序列，做成**真实键帽排**（见 §8），pending 键帽呈「按下」态——产品招牌交互件。
- **分级提示**：①提示该用哪类命令 → ②展示完整 par 解；看提示则星级封顶 1 星。
- **失败反馈**：diff 高亮差异 + 连续成功进度（第 k / N 次）。
- 撤销 `u` 自由使用，但作为 3 星条件之一。

## 7. 技术栈

- **Vue 3 + TypeScript + Vite**，组合式 API。
- 状态管理：Pinia（默认值，进度/星级为全局状态）。
- 进度存储：**localStorage，经 ProgressRepository 接口抽象**，后续可换后端；首版无账号无同步。
- 桌面优先，不做移动端适配（强键盘依赖）。
- **依赖面收敛（v2 硬条款）**：仅 `vue` / `pinia` / 可选 `@vueuse/core`。**不引 CSS 框架（含 Tailwind）、不引动效库、不引图表库**——设计侧已给完整 token 表，utility 框架只会稀释键帽母题，动效用 `<Transition>` + CSS token 足够。

## 8. 视觉语言：键帽母题（v2 替换原「明亮游戏化风」骨架）

### 8.1 母题与禁令（辨识度的来源）
- **视觉母题是「键帽」，不是「卡片」**——这是辨识度与反 SaaS 模板脸的单一总开关。所有可交互元素（命令键、按键回显、章节节点、星星）统一为键帽形态：圆角 6px、顶部 1px `inset 0 1px 0 rgba(255,255,255,.65)` 高光、底部 3px 同色深一阶实边（非投影），按下 `translateY(2px)` 且去掉底部边。
- **硬阴影取代模糊投影**：全局阴影 token 仅两个——`--shadow-1: 0 3px 0 var(--edge)`、`--shadow-2: 0 6px 0 var(--edge)`。禁止 `0 10px 15px rgba(0,0,0,.1)` 一类。
- 圆角阶梯：键帽 6 / 输入与大按钮 14 / 卡片 20 / 章节节点 10（不用 SaaS 8px）。
- 亮度分布反转：教学工具多为黑底终端风；本作定明亮风，编辑器区必须做**亮色纸面**（`--editor-bg: #FFFDF8`），不得偷懒做暗底终端。
- **首页禁止 hero 大标题+CTA**，改为「键帽墙」：散落排布的命令键帽（展示本课程将教的键）。
- 游戏化元素收敛为四项：**键帽指示灯 + 章节色路线 + 星级 + 齿孔通关卡**（原「连击 streak」撤回，见 §2.4E）。

### 8.2 色板
- 暖中性（不用冷灰）：`--paper #F6F4EE`（页面底）/ `--surface #FFFDF8`（卡片、编辑器底）/ `--edge #E4DFD2`（描边、硬阴影色）/ `--ink #2B2A26`（正文）/ `--ink-2 #6B675C`（弱文本）。
- 语义色每状态**两档**（fill 用于色块，ink 用于文字/描边）：主色 `#06B6D4`/`#0E7490`（✓AA）、正确 `#22C55E`/`#15803D`、错误 `#EF4444`/`#DC2626`、提示扣星 `#F59E0B`/`#B45309`、星级 `#EAB308`（仅图形）。
- **硬条款：正确/错误不得只用颜色区分**——必须叠加第二通道（✓/✕、`+`/`-` 前缀、位置、文案），红绿在 deuteranopia 下趋同。
- **章节色 = 单色相 cyan 明度 ramp 7 档**（ch1 `#CFFAFE` → ch7 `#0E7490`，浅→深 = 易→难），章节地图因此成为一条色深渐进的路线。使用规则：只做节点填充/顶部色带/进度条，**永不做大面积背景**（浅色阶撑不住）；浅色阶节点加 2px `--ink` 描边；**章节色永不表达对错**。

### 8.3 字体
- 界面：`Nunito`（圆润几何，呼应键帽；**刻意不用 Inter**——Inter 即 SaaS 脸本身）+ 中文系统栈（HarmonyOS Sans SC → Source Han Sans SC → PingFang SC → Microsoft YaHei）。
- 标题/数字：`Fredoka`，限 H1、星级数字、par 数字三处。
- 编辑器：`IBM Plex Mono`（0/O、l/1 有区分）+ CJK 等宽回退。
- **关键决策：拉丁上 webfont、中文不上 webfont**（中文 webfont 2–5MB 会直接崩首屏；此条与 §10 的 CJK woff2 棘轮互为表里）。
- 阶梯：`--fs-xs 12 / sm 14 / base 16 / lg 20 / xl 28 / 2xl 40`，行高 1.5（编辑器区 1.7），间距基线 4px，大按钮高 56px。

### 8.4 三屏视觉意象
- **章节地图**：垂直蜿蜒路线（不做侧边栏+卡片列表）。节点四态：
  | 状态 | 形态 |
  |---|---|
  | `locked` | 无色凹槽，inset 阴影，无徽标 |
  | `done` | 实心章节色 + ✓ 徽标 + 硬边 |
  | `current` | 实心 + 脉冲光晕 + 指针 |
  | `due-review` | **保持实心章节色**（不降饱和不调暗）+ 底部硬边改虚线 + 右上「复」字键帽徽标 + 1.8s 呼吸光（scale ≤1.03）|
  - `due-review` 与 `done` **差异只靠描边形态+徽标+运动，颜色完全一致**——色盲可辨，且不被误读为失去进度（调暗语义已专属于锁定态，混用等于变相锁关）。呼吸光在 `prefers-reduced-motion` 下降级为静态虚线。
  - 关内进度不用进度条，用**一排 N 个小键帽指示灯**（连续成功 k/N）——键盘指示灯的物理隐喻。
- **对局屏**：中央「纸面」编辑器（亮底、1px `--edge` 描边、硬阴影、行号槽弱化）；目标文本 `+`/`-` 前缀 + 绿底/红删除线（不靠颜色单独承载差异）；光标是全屏最亮元素（brand-ink 实心块，闪烁尊重 reduced-motion）；**按键回显栏做成真实键帽排**。
- **结算屏**：不做 modal，做整屏替换的「通关卡」：上缘**齿孔虚线**（`repeating-linear-gradient`，零资源）+ 黄铜星级 + 击键数 vs par 等宽数字效率条。不用 "🎉 Congratulations!"，不用 emoji 当主图标。

### 8.5 动效与反馈尺度
- 时长 token：`--dur-fast 120ms / base 200ms / slow 360ms`；缓动 `--ease-out cubic-bezier(.16,1,.3,1)`，仅星星与键帽弹入用 `--ease-out-back cubic-bezier(.34,1.56,.64,1)`（过冲 ≤1.15）。**禁用 linear**。
- 应答 ≤50ms：每次按键立即键帽下沉，不等判定。
- 成功：diff 行「盖章式」变绿（背景 + 左侧 4px 实色条）；失败：仅 diff 行红底 + `translateX ±4px` 抖两次共 160ms。**禁止全屏 shake**。
- 每次成功的动元素 ≤3 个；不做粒子/彩带，改用进度条一次性「扫光」。
- `prefers-reduced-motion: reduce`：所有 transform 动画降级为 120ms opacity 淡入。
- **工程约束**：不 transition `box-shadow`/`blur`/`drop-shadow`（不进合成层会掉帧）——键帽底边用 `::before` 实色块 + face 位移，「底边变矮」观感由位移自然产生；光晕用 `::after` radial-gradient 只动 scale+opacity；焦点环用 `outline`（跟随 border-radius 且不触发重排）。
- **硬条款：键盘完全可达、焦点永不丢失、Tab 顺序=视觉顺序**（每屏首个可聚焦元素是提示按钮）。这是键盘教学产品，此条优先于任何视觉细节。

## 9. 关卡与存储 schema（v2 增补）

### 9.1 进度记录 levelRecord
```
levelRecord = { levelId, streak, bestStars, bestKeys,
                attempts, lastPlayedAt, srsStage,   // uint 0–4
                schemaVersion }
```
- **`srsStage` 必须在 v1 冻结前加入**：若先按 `attempts` 跑一段再补，只能从 `attempts` 反推——而它把成功与失败混在一起，**从它推导会精确复制「失败也延长间隔」的方向性错误，迁移函数救不回来**，是唯一事后无法修正的方案。`schemaVersion` 从第一天存在。

### 9.2 关卡数据新增字段
- **`grid: boolean`**（默认 `true`）：IBM Plex Mono advance width 为 0.6em 非 0.5em，中英混排 CJK 落不上等宽栅格。含 CJK 的关卡置 `false`，**换掉栅格类线索不留空**——缩进参考线/制表刻度换成行号槽内行级标记（`⌷`/`+`）与 diff 徽标。这是逐关标志，不是全局禁令（第 7 章真实语料含中文是其存在理由）。
- **`texts: [{ start, target, cursor, parKeys }] × 2`**：替代单一 `startText/targetText`（见 §2.4B）。

### 9.3 内容校验器（构建期，扩展 §5 golden tests）
**规约会被忘，门禁不会**——五条断言违反即 fail，信息指到行号：
1. `grid !== false` 的关卡，`start`/`target` 不得含 CJK（U+4E00–9FFF、U+3000–303F、U+FF00–FFEF）。
2. 同一关 `texts[]` 变体：**行数相同且逐行前导空白完全相同**。
3. 变体 `cursor.line` 相同（列可不同，须同一行）。
4. `allowedKeys ⊆ 该章已教命令集 ∪ 往章`（§2.5 白名单）。
5. 每个变体的 `parKeys` 跑真引擎后确实收敛到该变体的 `target`。

### 9.4 项目结构（更新）
```
src/

  game/         # 关卡运行时：判定、连续计数、星级、白名单、提示
```

## 10. 资源策略（v2 新增）

### 10.1 资产白名单（棘轮，不是建议）
- 仓库只允许两类二进制资产：`.woff2` 与可选音频。**禁止一切光栅图**（png/jpg/webp/gif），唯一例外 `favicon.svg`。CI 跑 `git ls-files | grep -E '\.(png|jpe?g|gif|webp)$'`，命中即 fail。
- **同级棘轮**：`dist/assets/*.woff2` 不得含 CJK 覆盖（探针检测），CJK 一律系统栈。

### 10.2 图标：引入 0 个图标库
- ~10 个图标分三档：①平台覆盖稳的字形（箭头、`:`）直接用文本、`currentColor`、0 字节；②Esc/Enter/Backspace/Tab/Ctrl/Cmd/星/锁 8 个跨平台基线不稳的字形自绘 inline SVG 组件 `<KeyGlyph>`（`fill="currentColor"`，每个 200–500B，Vite 自动 tree-shake，顺带省掉 svg-sprite 插件依赖）；③判定规则：只有「通用符号且自绘 >5 分钟」才允许引第三方，实践预计 0–3 个。理由：2px 圆头描边的笔画语言（Lucide/Heroicons）就是模板脸的笔画语言。

### 10.3 插画：降级为组件 API
- 不引入任何插画包（undraw/humaaans 式扁平人物是模板脸最大来源，且与键帽母题冲突）。
- `<Keycap label width />` 一个参数化组件派生：首页键帽墙、章节节点、按键回显栏、指示灯、章末印章——**一套组件 = 全部插画资产**，0 字节、随 CSS 变量换色、随动效 token 动。庆祝感由齿孔 + 印章 + 星级动效承担，不靠位图。

### 10.4 音效：Web Audio 合成而非采样
- 键击 = 带通 ~1.5kHz 噪声 burst（3ms 攻击 / 40ms 衰减）；错误 = 低频方波两声；成功/升星 = 三音上行琶音。约 40–60 行 TS，0 字节、0 许可负担、音高按语义分档（与语义色双档同构）。
- 替换槽：Kenney.nl CC0 音频包（可商用免署名）取 3 个 ≈20–40KB 放 `public/audio/`，**首个关卡开始时才 fetch，绝不进首屏**。接口 `SoundPlayer`，实现可换。
- 硬条款：AudioContext 首次用户手势后 lazy init；静音开关持久化 localStorage；音频初始化失败静默降级，绝不阻塞判定或抛错。

### 10.5 字体
- 来源 Google Fonts（OFL 1.1），落地 `@fontsource-variable/*` npm 包——版本进 lockfile，离线自托管、可复现、无 CDN 运行时请求。子集化用官方包 `latin.css` + `unicode-range`，**不自己跑 pyftsubset**（OFL 的 RFN 条款是合规雷区）。
- 许可动作：OFL 文本落 `docs/licenses/`，`docs/LICENSES.md` 登记族名/版本，保留字体名与版权声明。
- `font-synthesis: none` + 显式数值字重；中文栈显式覆写 `line-height` 抵消字面差；编辑器字体 `<link rel=preload as=font crossorigin>`。
- CJK/Latin 字面差：`@font-face { font-family:"CJK Fallback"; src: local("PingFang SC"); size-adjust: 待目测; unicode-range: U+4E00-9FFF,… }` 收进命名栈校准——**≤2 次试调即冻结，不在 M3 前追求完美**（引中文等宽 webfont 单体 1MB+，撞碎「中文 0KB」棘轮）。

### 10.6 首屏预算（CI 断言口径）
| 项 | 目标 | 硬上限 |
|---|---|---|
| HTML+CSS+首屏 JS（gzip） | ≤140KB | 200KB |
| woff2 | ≤80KB | 120KB |
| 光栅图 | 0 | 0 |
| 首屏音频 | 0 | 0 |
| **合计** | **≤220KB** | **320KB** |

- 工具：`size-limit`（按 entry / css / woff2 glob）+ `rollup-plugin-visualizer` + `license-checker-rseidelsohn` 生成 `THIRD-PARTY.md`，CI 遇 GPL/AGPL 直接 fail。
- **woff2 超预算降级顺序（写死）**：①砍 Fredoka（H1/星级/par 数字改 Nunito 800）②Mono 只留 400 不留 600 ③`pyftsubset` 裁 ASCII + 教学字符集。注：80KB 目标在三套字体（Nunito VF ~35–45KB + Fredoka VF ~20–30KB + Plex Mono ~25–30KB）叠加下大概率不达，实测量级 80–105KB——**写死的是 120KB 硬上限 + 降级顺序 + CI 门禁，不是承诺值**（估计会错，门禁不会）。
- 懒加载：关卡数据按 `import.meta.glob` 分章成 chunk，章节地图只加载第 1 章；引擎留主 chunk。

## 11. 里程碑与验收（v2 修正）

### 11.1 里程碑
1. **M1 引擎**：教学子集全量实现 + golden tests 全绿。
2. **M2 游戏循环**：diff 制任务 + 连续计数 + 星级 + 白名单 + 分级提示 + localStorage 进度。**新增（约半天，与 localStorage 同批，这是它唯一正确的窗口）：`srsStage` 等存储字段 + `retentionOf` + 假时钟属性测试。**
3. **M3 MVP**：第 1–2 章关卡内容（**ch2 全量配变体，作者成本约 1–2 小时**）+ 教学卡 + 章节地图 UI + **热身卡（组件+选题器+90 秒计时，约 1 天，选题器纯函数可单测）**，完整可玩。
4. **M4+**：第 3–7 章内容批量产出 + 手感打磨；组块可视化（半天，P2 可插）。

### 11.2 M3 掉期砍单顺序（写死）
1. 砍热身卡 UI，**保留字段与选题器纯函数**（数据照收，UI 后补，掉期不产生迁移债）。
2. 砍 ch1 变体（标注已知妥协）。
3. **ch2 变体与毕业考 fresh 文本不可砍**——砍它等于让 M3 验证一个失真的判定器。

### 11.3 验收口径（两层拆分）
- **阶梯正确性** → `retentionOf` 假时钟属性测试全绿（单调 / 地板 0 / 封顶 4 / 同日只扩展一次 / 失败回缩），**不靠试玩**。
- **邀请动力学** → 两周试玩三个阈值：热身清关率 ≥80% 且单题失败 ≤1 次（低于 → 拉长 LADDER）；热身跳过率 <50%（高于 → 减到 2 题或弱化文案）；隔 7 天回归的 due 关卡首试失败率**非零但两次内可恢复**（为零=锈蚀没咬合真实遗忘，不可恢复=阶梯过陡）。**三个阈值只对 1d/3d 档读数**——两周内 7/14/30 档根本来不及触发。
- **试玩结论不得用于调 7/14/30 档**：那三个数只有文献支撑无数据支撑，如实标注「凭文献拍板，M4 后凭真实使用回看」。
- **免费健全性检查：rep 2 的 3 星率**——有变体轮换时应显著低于天花板；若几乎人手 3 星，说明变体没起作用或换得太浅。
- 已知风险照实记录：MVP 体量下 10–14 关 × 2 变体 ≈ 一周热身素材开始重复（内容深度问题，靠 ch3–7 填充）；换设备锈蚀清零（无同步，接受）；ch1 未配变体致热身清关率读数偏高（ch1/ch2 分层统计）。
